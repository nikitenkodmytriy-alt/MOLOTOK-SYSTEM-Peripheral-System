# MSPC OS 1.1

Лицензия: GNU GPLv2 или более поздняя версия. Прочитайте и подпишите двуязычное соглашение: [LICENSE.md](LICENSE.md).

MSPC OS - экспериментальная 32-битная операционная система для x86, написанная на C и NASM. Проект стартует на legacy BIOS, предоставляет текстовую командную строку, RAM-файловую систему, учетные записи, редактор, скриптовый интерпретатор, модульные драйверы и базовую сеть.

## Что входит

- BIOS-загрузка с ISO или USB.
- Командная строка MSPC.
- Встроенная RAMFS-подобная файловая система.
- Первый root-аккаунт и возможность нескольких root-пользователей.
- Полноэкранный текстовый редактор `etxt`.
- Интерпретатор `.mspc`-программ.
- VGA и PS/2-драйверы.
- PCnet, DHCP, ARP, IPv4, DNS и ICMP.
- Команды `ping`, `net`, `ifconfig` и `dns`.
- Отдельная папка `drivers/` с манифестами и исходниками.

## Быстрый старт

Требования в Linux:

- GCC с 32-битной компиляцией.
- NASM.
- GNU Make.
- Python 3.
- GNU binutils.

Сборка:

```sh
make
make test-all
make iso
make usb-image
```

Результаты:

- `build/kernel.elf` - ядро ELF32.
- `build/mspc-os.iso` - загрузочный BIOS ISO.
- `build/mspc-usb.img` - raw-образ для USB.
- `build/drivers.pack` - упакованные манифесты драйверов.

## Первый запуск

При первом старте система попросит создать имя и пароль начального root-аккаунта. Root может создавать других пользователей и передавать им root-права:

```text
useradd user1
passwd user1
su user1
root grant user1
root revoke user1
users
whoami
```

Пароли пока хранятся как учебный 32-битный хэш и не должны использоваться для защиты реальных данных.

## Команды

### Файлы

```text
ls [путь]
cd [путь]
pwd
mkdir <путь>
touch <файл>
cat <файл>
write <файл> <текст>
cp <источник> <назначение>
mv <путь> <новое_имя>
rm <путь>
tree [путь]
df
```

Файлы и папки находятся в RAM и исчезают после перезагрузки.

### Редактор etxt

```text
etxt файл.txt
```

Управление:

- Стрелки - перемещение курсора.
- Home/End - начало/конец строки.
- Insert - режим вставки или замены.
- Backspace/Delete - удаление символов.
- Ctrl+S - сохранить в RAMFS.
- Ctrl+Q - сохранить, отбросить или продолжить.

### Программы MSPC

Создать скрипт:

```text
etxt hello.mspc
```

Запустить:

```text
run hello.mspc
```

Поддерживаемые инструкции:

```text
print text
print $переменная
let имя число
show имя
add имя число
sub имя число
mul имя число
div имя число
input имя
if имя == число goto номер_строки
if имя != число goto номер_строки
if имя < число goto номер_строки
if имя > число goto номер_строки
goto номер_строки
cat путь
write путь текст
append путь текст
ping адрес
 dns имя
clear
end
```

Пример:

```text
let count 1
print Counting: $count
show count
add count 1
if count < 5 goto 3
end
```

Ограничения скриптов: 64 строки, до 128 символов на вводимой строке и максимум 1000 выполненных инструкций. Скрипты являются интерпретируемыми, а не машинным кодом.

## Сеть

Команды:

```text
net
ifconfig
dns example.com
ping 10.0.2.2
ping example.com
```

Реализованы PCnet PCI-драйвер, DHCP, ARP, IPv4, DNS A-записи и ICMP Echo. Для VirtualBox используется NAT-сеть, например `10.0.2.0/24`. Если DHCP не ответит, используются сетевые значения по умолчанию.

Для plain HTTP доступна команда `download http://host/path output-file`; она сохраняет ответ в RAMFS до лимита файла. HTTPS, распаковка архивов и скачивание папок пока не реализованы.

## Драйверы

Папка [drivers/](drivers/) содержит:

- VGA text-драйвер.
- PS/2 keyboard-драйвер.
- PCnet Am79C973-драйвер.
- DHCP/ARP/IPv4/DNS/ICMP-сетевой стек.

Манифесты имеют расширение `.drv` и упаковываются в ядро при сборке. Команды:

```text
drivers
driver load ps2-keyboard.drv
driver load vga-text.drv
driver load pcnet.drv
```

Драйвер загружается только если он уже зарегистрирован и связан с кодом ядра. Один `.drv`-файл не позволяет выполнить произвольный бинарный модуль с флешки.

## Установка на образ диска

Команды:

```sh
make install
```

Установщик работает только с обычным raw-файлом дискового образа. Он не принимает `/dev/sda`, VDI или другие виртуальные форматы напрямую.

Процесс:

1. Указать путь к raw-образу.
2. Выбрать номер MBR-раздела.
3. Подтвердить запись фразой `INSTALL <номер>`.

Установщик пишет загрузочный сектор выбранного раздела и ядро. MBR и остальные разделы не изменяются. Для запуска нужно настроить существующий загрузчик на цепную загрузку выбранного раздела.

## USB

Создать образ:

```sh
make usb-image
```

Файл: `build/mspc-usb.img`

Запись стирает содержимое выбранной флешки. Для записи нужно применять raw/DD-режим с проверкой устройства:

```text
/dev/disk/by-id/<точный-id-флешки>
```

Это legacy-BIOS USB-загрузка. UEFI пока не поддерживается.

## Ограничения версии 1.1

- Нет UEFI-загрузки.
- Нет постоянной файловой системы.
- Нет загрузки произвольных бинарных модулей с диска.
- Нет физического in-OS установщика на реальный диск.
- Нет компилятора C или native ELF-приложений.
- Есть host-тесты для FAT16/USB-копирования и software GL.
- Нет HTTPS и сертификатной проверки; HTTP-клиент пока plain TCP и сохраняет ответ в RAMFS до лимита файла.
- Внутри MSPC нет USB MSC/XHCI-драйвера; чтение флешки выполняется утилитой хоста `make usb-read`.
- Software GL 1.1 сейчас имеет точки/линии/треугольники в text VGA и интерактивный тест куба со стрелками и Esc и не является совместимым OpenGL 3/4.
- Нет безопасного современного хранения паролей.
- Лицензионное соглашение находится в LICENSE.md и содержит русскую и английскую редакции с подписью разработчика и получателя.
- Требуется проверка на реальной VirtualBox или hardware VM.

## Проверка сборки

Сетевые host-тесты:

```sh
make test-all
```

Тесты проверяют формирование DHCP, IPv4 и контрольных сумм, mock ARP/DNS/ICMP обмен и полный mock-путь `ping`.

Полная сборка:

```sh
make clean
make iso usb-image test-net
```
